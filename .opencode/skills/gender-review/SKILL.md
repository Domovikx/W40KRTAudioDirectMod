# Gender Review Skill

Проверка одного YAML-файла на несоответствие рода реплик полу голоса спикера.

## Источник истины по голосам

`config/voices.yaml` — каждый голос имеет `gender: male | female` и список `characters` (имена спикеров).
Чтобы узнать ожидаемый пол фразы: speaker из part → найти голос по characters (совпадение имени) → его `gender`.

Текущий маппинг (21 голос):
- **male (13):** kunrad, abelard, heinrix, pasqal, solomon, ulfar, marazhai, edelthrad, eogann, manipulus, trazyn, default_male, wh40k_narrator
- **female (8):** teodora, argenta, idira, cassia, jae, kibellah, yrliet, default_female

Роли NPC: `Smuggler`, `Psyker (NPC)`, `Seneschal (NPC)`, `Generic Male NPC`, `Arbites (NPC)`, `Interrogator (NPC)` → default_male (муж.).
`Generic Female NPC`, `NPC Female`, `female npc` → default_female (жен.).

## Как проверять (построчно, каждая фраза)

Для каждой фразы `phrases[]` смотреть `parts[]` (пропускать narrator-части: speaker = narrator/Narrator/system):

1. Определить ожидаемый пол по голосу спикера (см. выше).
2. Искать в `text_clean` маркеры рода говорящего:
   - **Прошедшее время 1-го лица:** «я сказал/сказала», «я был/была», «я пошёл/пошла», «я подумал/подумала», «я вернулся/вернулась», «я мог/могла», «я знал/знала»…
   - **Краткие прилагательные/причастия с «я»:** «я рад/рада», «я должна/должен», «я готов/готова», «я уверен/уверена», «я согласен/согласна», «я удивлён/удивлена», «я обижен/обижена»…
   - **Само-обращения:** «я — твоя/твой», «я ваша/ваш», «я сама/сам»…
   - **Наррация `{n}…{/n}` о говорящем:** «Женщина/девушка/дама/госпожа/контрабандистка/она …», «Мужчина/парень/юноша/господин/он …», «…сказала/сказал она/он»
3. **Правило:** текст явно противоречит полу голоса → `REVIEW`. Совпадает или род неясен → `OK`.

## НЕ флагить (ловушки)

- «хотел{mf||а}», «ты …{mf||а}» — род ИГРОКА, не спикера
- «она сказала…» в реплике — о третьем лице, не о спикере
- «мы…» — группа, род не читается
- Цитаты чужих слов внутри реплики («Она сказала: "я пришла"»)
- Наррация про другого персонажа сцены (в файле персонального героя может быть «мужчина подошёл к ней»)
- Самопредставление («Я — Кассия Орселлио»)

## Формат вывода (JSON-массив, только части!)

```json
[
  {
    "guid": "полный UUID",
    "part": 2,
    "status": "REVIEW",
    "suggested_speaker": "Jae Heydari",
    "note": "«я получила»/«Контрабандистка» — женский род, но speaker=Smuggler → default_male"
  }
]
```

- `part` — номер части (1-based!) из parts: parts[0] → part 1, parts[1] → part 2. ВАЖНО: не путать с 0-based индексами — укажи в note фрагмент text_clean, чтобы оркестратор мог сопоставить при сомнении
- `status`: `OK` или `REVIEW`. REVIEW — только при явном противоречии
- **Возвращай только REVIEW-записи.** Отсутствие фразы в выводе = все её части OK (проверены и не вызвали подозрений)
- `suggested_speaker` — кого ты считаешь правильным спикером (если определимо; иначе пусто/UNKNOWN)
- `note` — доказательства (маркеры рода + куда резолвится голос), на русском
- Фразы, где все части OK, можно не включать в вывод — но лучше включать с `status: OK`, чтобы оркестратор знал, что фраза пройдена

## Важно

- `speaker` и `speaker_override` НЕ ТРОГАТЬ — агент-триер read-only
- Результат выводить ТОЛЬКО как JSON (ничего другого в финальном сообщении)
